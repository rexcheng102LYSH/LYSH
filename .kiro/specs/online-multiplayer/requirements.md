# 联网对战功能需求文档

## 项目背景

Project Lysh（技能五子棋）计划添加简易联网对战功能，参考 PlayOK 五子棋的房间制对战模式。本阶段不涉及排位系统和自动匹配，仅实现基础的房间对战功能。

---

## 功能需求

### 核心功能

#### 1. 房间系统
- **创建房间**：玩家可创建房间，获得 6 位房间号
- **加入房间**：玩家输入房间号加入已存在的房间
- **房间状态**：等待中 / 游戏中 / 已结束
- **房间销毁**：游戏结束或双方离开后自动销毁

#### 2. 对战同步
- **落子同步**：一方落子后，另一方实时看到
- **回合控制**：服务端控制回合，防止抢先落子
- **胜负判定**：服务端验证胜负，防止作弊

#### 3. 连接管理
- **断线检测**：检测玩家掉线
- **断线处理**：给予 30 秒重连时间，超时判负
- **主动退出**：玩家可主动认输退出

### 可选功能（Phase 2+）

#### 4. 数据存储
- **对局记录**：存储每局棋谱
- **玩家昵称**：简单的昵称系统（无需注册）

#### 5. 技能系统（Phase 3+）
- **技能同步**：联网模式下技能使用同步
- **技能选择**：双方在开局前选择技能

---

## 非功能需求

### 性能要求
- 落子延迟 < 200ms（正常网络环境）
- 支持同时 100 个房间（初期目标）

### 兼容性
- 支持现代浏览器（Chrome、Firefox、Safari、Edge）
- 移动端浏览器基本可用

### 安全性
- 服务端验证所有落子合法性
- 防止伪造对方落子
- 房间号不可被遍历猜测

## 用户故事

### US-1: 创建房间
```
作为玩家 A，
我想要创建一个对战房间，
以便邀请朋友加入对战。

验收标准：
- 点击"创建房间"按钮
- 系统生成 6 位房间号
- 显示等待界面，展示房间号
- 可复制房间号分享给朋友
```

### US-2: 加入房间
```
作为玩家 B，
我想要通过房间号加入房间，
以便与朋友对战。

验收标准：
- 输入 6 位房间号
- 点击"加入房间"按钮
- 成功加入后进入游戏界面
- 房间不存在时显示错误提示
```

### US-3: 对战流程
```
作为对战双方，
我们想要进行一局完整的五子棋对战，
体验与本地对战一致。

验收标准：
- 房主执黑先行
- 双方轮流落子，实时同步
- 任一方五连时判定胜负
- 显示胜负结果，可选择再来一局
```

### US-4: 断线重连
```
作为玩家，
当我意外断线时，
我希望能重新连接继续对局。

验收标准：
- 断线后 30 秒内可重连
- 重连后恢复棋盘状态
- 超时未重连判定为认输
```

## 技术约束

### 必须遵守
- 前端保持原生 JS，不引入框架
- 后端使用 Node.js + Socket.IO
- 与现有代码架构兼容

### 建议遵守
- 联网模块独立，不影响本地对战功能
- 代码结构清晰，便于后续扩展技能同步

## 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 网络延迟导致体验差 | 中 | 优化协议，减少数据包大小 |
| 服务器成本 | 低 | 初期使用免费托管方案 |
| 作弊问题 | 中 | 服务端验证所有操作 |
| 技能同步复杂度高 | 高 | 先实现无技能版本 |
